# Data dictionary

All sensor data in this folder is **synthetic** (generated by software). It is not a real seismic recording.
Amplitude, frequency, duration and noise values are invented by the simulation model for teaching the
algorithms. Only `usgs_sample_catalog.csv` contains real data, and it holds no sensor readings.

## `seismic_sensor_readings.csv` (synthetic sensor readings)

Lines starting with `#` are comments. The first non-comment line is the header. Column order does not
matter, and header names are case-insensitive. The aliases in brackets are also accepted on import.

| Column | Type | Unit | Required | Valid range / rule | Meaning |
|---|---|---|---|---|---|
| `reading_id` [`id`] | text | – | yes | non-empty, unique in the file | Identifier of the reading (`D00001`...) |
| `sensor_id` [`sensor`] | text | – | yes | must exist in `sensors.csv` | Virtual sensor that produced the reading |
| `timestamp_utc` [`timestamp`, `time`] | ISO-8601 instant | UTC | yes | after 2000-01-01, at most 1 day in the future | Time of the reading, e.g. `2026-10-01T08:00:15Z`. `yyyy-MM-dd HH:mm:ss` is also accepted and read as UTC |
| `amplitude` | decimal | synthetic normalised units | yes (value) | 0.0 – 2.0 (sensor range) | Peak ground-motion amplitude. **Not** a magnitude. Detection thresholds: 0.30 / 0.50 / 0.75 |
| `frequency_hz` [`frequency`] | decimal | hertz | column yes, value optional | > 0 and ≤ 100 | Dominant frequency. Simulated seismic shaking is 2–6.5 Hz; electrical glitches are 20–45 Hz |
| `duration_s` [`duration`] | decimal | seconds | column yes, value optional | 0 – 300 | Duration of the signal burst. Spikes are < 0.3 s; shaking is 1.5–4 s |
| `noise_level` [`noise`] | decimal | ratio 0–1 | column yes, value optional | 0 – 1 | Estimated noise share of the signal. ≥ 0.6 makes the reading SUSPICIOUS |
| `scenario_label` [`label`] | text | – | no | free text | Ground truth written by the generator: `NORMAL`, `MINOR_EVENT`, `MAJOR_EVENT`, `WEAK_EVENT`, `ISOLATED_SPIKE`, `SENSOR_FAULT`, `NOISY_DATA`, `INVALID_DATA`, or `ERROR_*` for deliberately broken rows. The engine **never** uses this label for detection; it exists only to check results |

### Validation outcome of each row

| Outcome | When | What happens |
|---|---|---|
| **Rejected** | wrong column count, missing/duplicate `reading_id`, missing or unknown `sensor_id`, unparseable or implausible timestamp, broken quoting | Row is listed on the *Rejected rows* tab with its line number and reason; it is not used |
| **INVALID** | amplitude missing, not a number, negative or > 2.0; frequency ≤ 0 or > 100; duration < 0 or > 300; noise outside 0–1 | Row is kept and flagged, excluded from detection, and lowers the sensor's reliability |
| **SUSPICIOUS** | noise ≥ 0.6 or amplitude ≥ 1.8 | Kept and filtered, but not used for multi-sensor correlation |
| **VALID** | everything else (missing *optional* values are noted) | Used by every algorithm |

## `sensors.csv` (virtual sensor network)

| Column | Type | Unit | Meaning |
|---|---|---|---|
| `sensor_id` | text | – | `S01` … `S15` |
| `sensor_name` | text | – | e.g. `Central Station A` |
| `zone` | text | – | `Central`, `North`, `East`, `South`, `West` (three sensors each) |
| `latitude`, `longitude` | decimal degrees | WGS-84 | **Illustrative** coordinates: zone centres about 30 km apart, sensors 2.5–5 km apart inside a zone. An empty value means unknown coordinates |

## Other files

| File | Content |
|---|---|
| `sample_import_with_errors.csv` | Small synthetic import example: 30 valid rows plus typical mistakes (negative amplitude, zero frequency, noise > 1, noisy row, bad timestamp, unknown sensor, missing columns, missing optional values) |
| `sample_missing_columns.csv` | A file without the `amplitude` and `noise_level` columns, to show the "missing required column" error |
| `usgs_sample_catalog.csv` | **Real** public data: the USGS "M4.5+ earthquakes, past week" feed, downloaded on 2026-10-13 from `https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/4.5_week.csv`. Columns follow the [USGS CSV format](https://earthquake.usgs.gov/earthquakes/feed/v1.0/csv.php). Used only for the separate *Earthquake catalog (real)* tab |

### USGS catalog columns used by the application

| Column | Unit | Meaning |
|---|---|---|
| `time` | ISO-8601 UTC | Origin time |
| `latitude`, `longitude` | degrees | Epicentre |
| `depth` | km | Hypocentre depth |
| `mag`, `magType` | magnitude scale | Reported magnitude and its type (`mb`, `mww`, ...) |
| `id` | – | USGS event ID |
| `place` | – | Text description of the location |

The other USGS columns are ignored. Catalog rows are never turned into sensor readings: the catalog contains
no sensor IDs, amplitudes, frequencies or noise levels, and inventing them would be fabricating data.
